## 5. Lấy dữ liệu & cache

### 5.1 Quy tắc
- Chỉ lấy dữ liệu ở Server Component qua `lib/data/*`. Mỗi hàm: nhận tham số đã kiểm (page, filters), gọi Payload Local API với `depth` thấp (1–2), `select` chỉ các trường cần, `overrideAccess: false` (đọc theo quyền ẩn danh) và `locale: 'vi'`.
- Hàm danh sách luôn có `limit` và `page`. Không `limit: 0`.
- Khi bật Draft Mode (mục 8): truyền `draft: true` và **không** dùng cache.

### 5.2 `lib/cache.ts`
```ts
import { unstable_cache } from 'next/cache'

export function getCached<T>(
  keyParts: string[],
  tags: string[],
  fn: () => Promise<T>,
  revalidate = 3600,
): Promise<T> {
  return unstable_cache(fn, keyParts, { tags, revalidate })()
}
```
Ví dụ: `getCached(['article', slug], ['articles', `article:${slug}`], () => payload.find({...}))`.
- Payload Local API không dùng `fetch`, nên **bắt buộc** bọc `unstable_cache` thì mới có ISR theo tag. (Hàm này đã được Next đánh dấu cũ trong 16 nhưng vẫn hỗ trợ; Payload ghi nhận chưa hỗ trợ `use cache`/Cache Components. **Không chuyển sang `use cache` trong dự án này.**)
- `revalidate` mặc định 3600 giây làm lưới an toàn; cập nhật thực tế do tag.
- Trang có tham số động dùng `generateStaticParams` cho **tối đa 50 bản ghi mới nhất**, còn lại sinh theo yêu cầu (`dynamicParams = true`).

### 5.3 Tag (phải khớp `02-CMS-BE.md` mục 6)
`articles`, `article:{slug}`, `products`, `product:{slug}`, `producers`, `producer:{slug}`, `events`, `event:{slug}`, `legal-docs`, `destinations`, `destination:{slug}`, `home`, `landing:{key}`, `site-settings`, `sitemap`.

**Gắn tag đúng thì mới cập nhật đúng:** trang chủ phụ thuộc `home` + `articles`/`products`/... (khối featured); trang danh sách gắn tag của loại tương ứng; trang landing gắn `landing:{key}` + tag loại bản ghi đang ghim.

## 6. Revalidate khi xuất bản (≤ 5 giây)

- Khi biên tập viên bấm Publish trực tiếp trên `/admin` (chạy trong container `web`), hook `revalidateOnChange` của Payload gọi trực tiếp trong cùng tiến trình:
  ```ts
  import { revalidateTag, revalidatePath } from 'next/cache'
  revalidateTag(tag, { expire: 0 })   // hết hạn ngay, yêu cầu kế tiếp tạo lại
  revalidatePath(path)                // thêm cho trang chi tiết nếu cần
  ```
  `updateTag` chỉ dùng trong Server Action nên không dùng ở hook. `'max'` (stale-while-revalidate) **không** dùng cho xuất bản vì người đọc có thể thấy bản cũ.
- **Xử lý xuất bản hẹn giờ từ container `jobs`:** Container `jobs` chạy ở tiến trình riêng nên gọi `revalidateTag` tại `jobs` không xóa được bộ nhớ cache của container `web`. Do đó, bổ sung route nội bộ `src/app/(frontend)/api/internal/revalidate/route.ts` (chỉ nhận `POST` với header `x-cron-secret === process.env.CRON_SECRET`; bị Nginx chặn hoàn toàn từ Internet vì nằm ngoài `/api/public/*`). Khi `process.env.IS_JOBS_WORKER === 'true'`, hook `revalidateOnChange` gọi `fetch(process.env.INTERNAL_WEB_URL + '/api/internal/revalidate', ...)` để container `web` thực thi `revalidateTag(tag, { expire: 0 })`.
- Spike S3 phải chứng minh: cả bấm Publish trực tiếp lẫn xuất bản hẹn giờ (`schedulePublish`) → tải lại trang bài và trang chủ → thấy nội dung mới trong ≤ 5 giây **trên bản build production**.

## 8. Preview, ảnh, font

### 8.1 Xem trước bản nháp
- `GET /api/preview?secret=<PREVIEW_SECRET>&path=/...`: kiểm secret, `draftMode().enable()` (async), redirect tới `path`. Chỉ nhận `path` bắt đầu bằng `/` (chặn open redirect).
- `GET /api/preview/exit`: tắt Draft Mode.
- Trang chi tiết: nếu `(await draftMode()).isEnabled` → đọc với `draft: true`, không cache, hiển thị dải "Đang xem bản nháp" + nút thoát.
- Chỉ người đã đăng nhập admin mới dùng được: Payload `admin.preview` sinh URL kèm secret; route kiểm `secret` **và** (khuyến nghị) cookie phiên Payload qua `payload.auth({ headers })`.

### 8.2 Ảnh (`components/ui/MediaImage.tsx`)
- Luôn dùng `next/image` với `loader={ocopMediaLoader}`; truyền `width`/`height` hoặc `fill` + `sizes`.
- Hiển thị `credit`/`caption` từ `media` (bài báo bắt buộc ghi nguồn ảnh).
- `alt` lấy từ `media.alt`; nếu trống (ảnh trang trí) → `alt=""`.
```ts
// lib/media-loader.ts
import type { ImageLoaderProps } from 'next/image'

export default function ocopMediaLoader({ src, width }: ImageLoaderProps): string {
  if (src.startsWith('http://') || src.startsWith('https://')) return src
  const base = process.env.NEXT_PUBLIC_MEDIA_URL || ''
  const preset = width <= 400 ? 'thumb' : width <= 640 ? 'w640' : width <= 1080 ? 'w1080' : 'w1920'
  return `${base}/media/img/${preset}/${src.replace(/^\/+/, '')}@webp`
}
```
- `next.config.mjs`: **không** khai báo `remotePatterns` cho `lh3.googleusercontent.com`; `images.loader = 'custom'` với `loaderFile`.
- Đường dẫn `src` là `media.filename` (ví dụ `2026/11/<uuid>.jpg`); Nginx/imgproxy xử lý ở `03`.

### 8.3 `next.config.mjs` (tối thiểu)
`output: 'standalone'`, `typescript.ignoreBuildErrors = false`, `eslint.ignoreDuringBuilds` không đặt, bọc `withPayload(...)`, `images: { loader:'custom', loaderFile:'./src/lib/media-loader.ts' }`, `poweredByHeader: false`, `redirects()` như mục 7.6.

- Trường theo `02` mục 7.1: loại gửi, chuyên mục đích, tỉnh, thông tin người gửi, tiêu đề, tóm tắt, nội dung (textarea thuần), tối đa 5 tệp (jpeg/png/webp/pdf/docx, ≤ 20 MB mỗi tệp, tổng ≤ 50 MB), **ô tick đồng ý** kèm link chính sách quyền riêng tư, Cloudflare Turnstile.
- Gửi `multipart/form-data` tới `POST /api/public/submissions`. Thành công → hiện `trackingCode` to, rõ, có nút sao chép và lời nhắc "hãy lưu mã này". Lỗi → thông báo tiếng Việt từ API.
- Validate phía client bằng zod (cùng quy tắc với server) nhưng **server vẫn là nơi quyết định**.
- Chặn gửi lặp (disable nút khi đang gửi). **Không** dùng `alert()`.
- Tra cứu: `GET /api/public/submissions/track?code=&email=`; hiển thị đúng thông điệp API trả về; không suy đoán thêm.

## 12. Tiêu chí nghiệm thu FE (Definition of Done)

1. `pnpm lint`, `pnpm type-check`, `pnpm build` xanh với `ignoreBuildErrors = false`.
2. Không còn `*.html` trong link, không còn `lh3.googleusercontent.com`, không còn mảng dữ liệu nội dung viết cứng trong `src/` (kiểm bằng `grep` trong CI).
3. 30 route ở mục 4 hiển thị dữ liệu thật từ CMS; slug sai → 404; slug đã đổi → 301.
4. Sửa/xuất bản trong admin → trang chi tiết và trang chủ đổi trong ≤ 5 giây (build production).
5. Lighthouse (mobile, trang chủ + trang bài + trang danh sách sản phẩm trên staging): **LCP ≤ 2,5 s, CLS ≤ 0,1, INP ≤ 200 ms, Accessibility ≥ 90, SEO ≥ 95**.
6. Tìm kiếm: `?q=tra tan cuong` ra "Trà Tân Cương"; không kết quả → `EmptyState`.
7. Gửi bài thật có tệp đính kèm → nhận `trackingCode` → tra cứu được.
8. Bàn phím: điều hướng được toàn bộ menu, modal tìm kiếm, form; có `focus-visible`; ảnh có `alt`.
9. Không có thanh cuộn bị ẩn; font nạp 1 lần; logo đúng kích thước.
